# 指标口径

| 指标 | 口径 | 单位 | 维度 |
|---|---|---|---|
| `aov` | 已支付 GMV / 已支付订单数 | 元 | 渠道、等级、城市、年龄 |
| `upt` | 已支付件数 / 已支付订单数 | 件/单 | 渠道、品类 |
| `return_rate` | 退货件数 / 销售件数 | % | 品类 |
| `discount_rate` | 折扣金额 / 吊牌金额 | % | 渠道、等级 |
| `member_gmv` | 已支付 GMV | 元 | 渠道、等级 |
| `refund_amount_rate` | 退款订单金额 / 全部订单金额 | % | 渠道 |
| `new_members` | 期内首次注册会员数 | 人 | 注册渠道、城市、年龄 |
| `orders_per_member` | 已支付订单数 / 有购买会员数 | 单/人 | 等级、城市 |
| `repurchase_rate_90d` | 近 90 天购买 ≥2 次会员 / 近 90 天购买 ≥1 次会员 | % | 注册渠道、等级、城市、年龄 |
| `active_rate_30d` | 期末前 30 天有购买或行为 / 期初已注册 | % | 等级、城市、年龄 |
| `churn_rate_180d` | 期末前 180 天无购买 / 期初有购买 | % | 等级、城市 |
| `repeat_gmv_share` | 期内 ≥2 单会员贡献 GMV / 总 GMV | % | 等级 |

## 两个容易踩的口径陷阱

### 1. 复购率不能用"首单 cohort"做月度监控

首单 cohort（"某月首单，90 天内是否复购"）会受**右删失**影响：最近一个月首单的会员还没走完 90 天，复购率必然趋近 0。用它做月报，会把"观察期不足"误读成"业务崩塌"。

实测对比（同一份数据）：

```
首单 cohort 口径：9 月 0.6%，8 月 9.7%   ← 看起来崩了
滚动窗口口径：    9 月 12.4%，8 月 14.3% ← 真实变化
```

本项目的 `repurchase_rate_90d` 采用滚动窗口。cohort 口径仍有价值（评估拉新质量），但不用于月度监控。

### 2. 复购率不能按订单渠道切

复购率的分母是**会员**，订单渠道是**订单**属性。一个会员可以在多个渠道下单，按订单渠道切会让人被重复计入多个组。

所以 `repurchase_rate_90d` 只允许 `register_channel`（注册渠道），`aov` 才允许 `channel`（订单渠道）。这个限制写在 YAML 里，`metricguard ask "9月复购率按渠道"` 会自动改用注册渠道并提示。

## 为什么维度写在 YAML 而不是代码里

维度白名单是**契约的一部分**：它决定了"这个指标可以被怎样切"。改代码可以偷偷放宽限制，改 YAML 会留下 diff。审计时看的是 diff。

## 版本

每个指标带 `version`。口径变更时递增，并在审计日志里可追溯（同一指标不同版本可能给出不同数值，这是特性不是 bug）。
